# Interview

Ask at most these five, one at a time. Skip any the files, repo or the user's first message already answer. If the user dumps everything at once, ask nothing that is covered.

1. Portfolio or product site, and what is the one action a visitor should take?
2. Who visits?
3. Two or three sites you like and one you hate, and why?
4. What real material exists?
5. How bold: quiet, expressive or experimental?

## What each answer changes

| Answer | Decides |
| --- | --- |
| 1 | Mode, page list, the primary call to action |
| 2 | Tone, vocabulary, what appears first |
| 3 | Palette, type, layout grammar. Take qualities, never copy a site. The hated site is a list of things to avoid |
| 4 | Which sections exist. A section with no material is dropped |
| 5 | Motion, signature moments, whether WebGL is considered |

## When the user says "you decide"

Choose, say what you chose and why in one line, and put it in the brief as your choice so they can reject it. Choose from this subject, not from habit.

## Then write the brief

Fill the template in [design-motion.md](design-motion.md): Concept, Audience, Palette, Type, Layout grammar, Motion, Signature, Texture. Say which of the user's answers each choice came from. Stop and wait for approval before writing UI code.
